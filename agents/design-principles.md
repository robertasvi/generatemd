# Visual Design Principles for Agent Interfaces

This document establishes the UI/UX design standards, typography scales, layout rules, and accessibility guidelines for all visual outputs, widgets, and user-facing components generated by or for the agent.

---

## 1. Core Visual Pillars

### A. Clarity Over Novelty
- **Information Hierarchy:** Every visual output must guide the user's eye naturally from primary summaries to granular details using strong typographic scale (Headers, Body, Captions).
- **Zero Clutter:** Avoid redundant text, unformatted raw JSON walls, or unnecessary decorative icons. Every visual element must serve an operational or cognitive purpose.

### B. Contextual Scannability
- **Structured Layouts:** Prefer tables, cards, and sequential blocks over wall-to-wall text for data comparisons or multi-step processes.
- **Progressive Disclosure:** Keep initial outputs concise and high-level, offering interactive drill-downs or clear next steps for deeper investigation.

### C. Cohesive Brand & System Language
- **Unified Tokens:** Stick strictly to established design system tokens (colors, radii, spacing, shadows) rather than arbitrary inline styles.
- **Purposeful Interactivity:** Interactive elements (buttons, sliders, toggles) must look clickable and provide immediate visual feedback upon interaction.

---

## 2. Typography & Text Hierarchy

| Level | Size / Weight | Usage |
| :--- | :--- | :--- |
| **Heading 1 (`#`)** | 24px - 32px (Bold) | Page titles, primary modal headers |
| **Heading 2 (`##`)** | 20px - 24px (Semi-bold) | Major section dividers |
| **Heading 3 (`###`)** | 16px - 18px (Medium) | Sub-sections, component titles |
| **Body Text** | 14px - 16px (Regular) | Paragraphs, descriptions, list items |
| **Caption / Meta** | 12px (Regular/Muted) | Footnotes, timestamps, helper text |

- **Line Length:** Maintain comfortable reading line lengths (roughly 50 to 75 characters per line for body copy).
- **Line Height:** Ensure generous leading (`1.5` or greater) to prevent text crowding.

---

## 3. Color & Contrast Standards

- **Accessible Contrast:** All text must meet WCAG AA standards (minimum 4.5:1 contrast ratio for normal text, 3:1 for large text against its background).
- **Semantic Color Meaning:**
  - **Primary/Accent:** Used for primary actions, active states, and focus rings.
  - **Success (Green):** Completed tasks, positive metrics, validations.
  - **Warning (Yellow/Amber):** Cautionary states, pending reviews, threshold alerts.
  - **Error (Red):** Failures, destructive actions, validation errors.
- **Dark Mode Compatibility:** All color choices must adapt cleanly between light and dark themes using semantic design tokens rather than hardcoded hex values.

---

## 4. Spacing, Layout, & Grid System

- **8pt Grid System:** All padding, margins, and layout dimensions must be multiples of 8px (`8px`, `16px`, `24px`, `32px`, etc.) to maintain consistent visual rhythm.
- **Generous White Space:** Never pack components edge-to-edge. Separate heavy widgets with clear vertical padding and visual dividers (`---` or border lines).
- **Responsive Fluidity:** Layouts must reflow cleanly from desktop multi-column grids down to single-column stacked views on mobile viewports.

---

## 5. Accessibility (a11y) & Inclusivity

- **Keyboard Navigation:** All interactive elements must be focusable and fully operable via keyboard (`Tab`, `Enter`, `Space`, arrow keys).
- **Screen Reader Support:** Interactive widgets and custom graphical elements must include descriptive ARIA labels, alt text, or text-equivalent readouts.
- **Color Independence:** Never rely on color alone to communicate state (e.g., always pair red error text with an icon or clear text label).s
