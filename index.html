Why keep these files?

AI coding assistants only know what is in the prompt and the repository. These files give every developer's assistant the same shared context, so suggestions follow team decisions instead of generic habits.

AGENTS.md

The single source of truth about the project: purpose, stack, design, testing and workflow rules. It shortens onboarding for people and agents, and keeps generated code consistent across the team.

SKILL.md

Packages a repeatable task, such as release notes or a code review, into steps the agent follows the same way each time. Good tasks are written once, reviewed by the team and reused instead of re-explained in every chat.

Rules (.instructions.md)

Targeted standards that apply only to matching files, for example models or exception handling. They keep the agent focused, avoid bloating AGENTS.md, and turn review comments into rules that are applied automatically.

Treat them as code: keep them in the repository, review changes in pull requests and update them whenever a convention changes. Outdated instructions lead to outdated suggestions.

Where to keep them

my-project/
├── AGENTS.md                         <- project-wide instructions
├── .github/
│   ├── AGENTS.md                     <- alternative location
│   ├── instructions/

│   │   └── exceptions.instructions.md
│   └── skills/
│       └── create-release-notes/
│           └── SKILL.md              <- one folder per skill
├── src/
└── package.json
